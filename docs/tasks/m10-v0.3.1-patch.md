## M10-1 — `#111`: a local `Close` always wins over `Reset`

**Status:** done — #120
**Issue:** #111
**Depends on:** —
**Blocks:** `M10-2` (same lines of `conn.go`)

**Cause:** `Read` and `Write` checked `c.closed` and `c.resetCh` in one non-blocking `select`. Once both are closed, Go picks between ready cases pseudo-randomly, so a conn that was reset and then closed locally failed with `net.ErrClosed` or `ECONNRESET` depending on the runtime, not the seed. That contradicts `conn`'s own `Close` contract ("this end's own subsequent Read/Write fail immediately with … `net.ErrClosed`") and a real `net.Conn`.

**Scope:**
- `conn.go` `Read`/`Write`: split the leading check into two sequential non-blocking `select`s — `c.closed` first, then `c.resetCh`. The blocking `select`s further down stay merged; they only wake the loop, which re-runs the ordered checks.
- Godoc on `Read`/`Write` and `Network.Reset` states the precedence. `docs/04-api-design.md#mid-stream-connection-reset` and `docs/05-fault-injection.md#mid-stream-connection-reset` gain the same sentence.

**Out of scope (deferred):** the issue's optional note that `Set*Deadline` checks `c.closed` and arms its timer without one lock across both steps, so a racing `Close` could in theory leave a re-armed timer. Never observed (20,000 races in the issue's own run), and harmless if it happened — the stray timer fires once and only wakes a channel. Not worth widening a patch for.

**Tests** (`reset_test.go`): `TestResetThenCloseIsDeterministicallyClosed` (10,000 iterations of `Reset` → `Close`; `Read` and `Write` always `errors.Is(err, net.ErrClosed)`, and the un-closed peer still sees `ECONNRESET`), `TestCloseThenReset` (the reverse order). The existing `TestResetSurfacesECONNRESETToReader`/`Writer`/`TestResetConnectionStaysReset` guard that `Reset` without `Close` still yields `ECONNRESET`.

## M10-2 — `#113`: build on plan9

**Status:** done — #121
**Issue:** #113
**Depends on:** `M10-1`
**Blocks:** —

**Scope:**
- Move the reset error behind a platform split: `reset_errno.go` (`//go:build !plan9`, `syscall.ECONNRESET`) and `reset_errno_plan9.go` (`//go:build plan9`, an error with the same message). `conn.go` uses the shared identifier and drops its `syscall` import. Behaviour on every other platform is unchanged.
- CI (`.github/workflows/ci.yml`, `stable` leg): a cross-build step over `plan9/amd64`, `windows/amd64`, `darwin/arm64`, `js/wasm`, `wasip1/wasm`. This step is the task's red: run it before the fix and see `undefined: syscall.ECONNRESET`.
- Godoc on `Read`/`Write`/`Reset` and the `ECONNRESET` mentions in `docs/04`/`docs/05` note the plan9 fallback.

**Not covered:** the test files keep using `syscall.ECONNRESET`, so `go vet`/`go test` still don't compile on plan9. The issue's done-when is `go build ./...`.

## M10-4 — `#114`: named panic for a nil option

**Status:** done — #123
**Issue:** #114
**Depends on:** —
**Blocks:** —

**Decision (maintainer):** panic with a named message rather than skip nil entries — it matches every other misuse rule in [docs/04 § Error and no-op behaviour](../04-api-design.md#error-and-no-op-behaviour), and turning an anonymous crash into a named one is not a behaviour change a patch must avoid.

**Scope:** `NewNetwork` panics with `netchaos: NewNetwork: nil Option at index N`; `DialerFor` panics at call time (not at dial time) with `netchaos: DialerFor: nil DialerOption at index N`. New bullet in `docs/04` § Error and no-op behaviour; a line in both godocs.

**Tests** (`options_test.go`, reusing `expectPanic`): `TestNilOptionPanicsWithName`, asserting both exact messages, including a non-zero index.

## M10-5 — `#108`: correct the skill and `docs/04` on dialers

**Status:** done — #124
**Issue:** #108
**Depends on:** —
**Blocks:** —

**Scope:**
- `.claude/skills/netchaos/SKILL.md` and `references/api.md`: an unnamed `Dial` is never partition-targetable and never blocks; a *named* dial (`DialerFor`/`WithPeerName`) blocks on a partitioned peer until `WithDialTimeout` or its context ends the wait. Separate the dialer shapes: `DialContext` fits `http.Transport.DialContext`; `Dial`/`DialerFor` have `net.Dial`'s shape; gRPC's `WithContextDialer` needs a two-argument adapter.
- `docs/04-api-design.md`'s `DialContext` block, and the real godoc in `netchaos.go` if it says the same.
- Editing the skill outside a close-out is justified: these statements were already wrong for `v0.3.0`, so correcting them makes the skill describe the tagged release *more* accurately.

**Red:** `grep -rn "hangs forever\|exact shape" .claude/skills docs` returns hits. The quoted historical sentence in `m5-hardening-and-ergonomics.md` stays as a record and is the one accepted hit afterwards.

**Tests** (`api_test.go`): compile-time assertions for `DialContext`'s three-argument shape and a gRPC-shaped adapter, plus `TestPlainDialIgnoresPartition`. These pass on first run — the code was already right — so the grep above is this task's red.
